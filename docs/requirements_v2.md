## 0. この文書の位置づけ

現行 v10（rulebook v15 / 801ルール）を、「クライアント業種を選び → 媒体を選び → その組み合わせに最適化した見解を返す」プロダクトへ作り替えるための要件定義。データベース・診断エンジン・UIの全面刷新を含む。実装モデルは最終的に Claude Fable 5（`claude-fable-5`）へ寄せる。

## 1. 現状（As-Is）と課題

### 1.1 いまの構造
- `rulebook.json`：RB 610 + EX 19 + CS 172 ＝ 801件を `[id, ng, risk, genre, comment, ok, law, jcia]` のタプル配列で保持
- フロント `matchRules()`：入力文への単純な部分一致／キーワード一致でルールを拾う
- ヒットした中から**上位10件だけ**をAIにコンテキストとして渡す（`claude-sonnet-4-6`）
- Stripe課金ゲート（無料6回→有料）実装済み

### 1.2 課題（v2で潰す）
| # | 課題 | 影響 |
|---|---|---|
| C1 | マッチングが素朴な文字列一致。言い換え・表記ゆれ・文脈を拾えない | 見逃し（偽陰性）が出る＝一次診断の信頼性が頭打ち |
| C2 | ヒットしても上位10件で足切り | 長文・複数論点の広告で観点が漏れる |
| C3 | **業種の概念がない**。健康食品/化粧品前提のルールに、整体・クリニック・エステが混在して当たる | 業種違いの誤検知・的外れな修正案 |
| C4 | **媒体の概念がない**。LP・SNS・院内掲示で「広告該当性」も要件も違うのに一律判定 | 医療広告GLの限定解除・ステマ規制などを正しく当てられない |
| C5 | データがタプル配列で意味が薄い（業種タグ・媒体タグ・条文構造なし） | 拡張・検索・スケールの土台がない |
| C6 | UIが機能優先。視認性・情報設計がプロ水準でない | 対外的な信用資産としての見栄えが弱い |

## 2. ビジョンとゴール（To-Be）

### 2.1 コンセプト
> 「あなたの業種」×「出す媒体」を選ぶと、その現場に効く薬機法・景表法・各業種ガイドラインの一次診断が返る。素人が触ってもプロが設計したと分かるUI。

### 2.2 成功条件（測れる形で）
- G1：業種×媒体を選択してからの診断で、業種違いの誤検知が現行比で実感として消える
- G2：言い換え・表記ゆれの見逃しが減る（意味検索の導入）
- G3：UIが「プロのアプリ制作者が作った」水準（下記 §9 の受入基準を満たす）
- G4：診断エンジンを Fable 5 に載せ、精度を回帰テストで担保
- G5：まさのコンサル受注導線（B2B信用資産）として機能する

## 3. クライアント業種体系（コアの新設計）

まさの専門（医療広告・薬機法・景表法）が規制としてかかる業種を、**適用法令の性質**で5カテゴリに整理する。判定軸が変わる＝カテゴリを分ける理由。

### 3.1 カテゴリと業種一覧

| カテゴリ | 業種（ユーザーが選ぶ単位） | 主に効く規制 | 業種特有の落とし穴 |
|---|---|---|---|
| **A 医療機関** | 病院／クリニック（診療所）／美容クリニック・美容皮膚科／歯科医院／精神科・心療内科 | 医療法（医療広告GL 2018改正）、療担規則 | 体験談・ビフォーアフター原則禁止、限定解除要件（自由診療は費用・リスク・副作用明記）、「絶対安全」「必ず治る」NG、広告可能事項の限定列挙 |
| **A' 助産・在宅** | 助産院（助産所）／訪問看護ステーション／調剤薬局 | 医療法、母子保健法、保助看法、薬機法 | 助産所は「病院」「クリニック」を名乗れない・正常分娩のみ・嘱託医連携表示、薬局は薬機法の表示規制 |
| **B 施術系（国家資格）** | 整骨院・接骨院／鍼灸院／あん摩マッサージ指圧 | 柔道整復師法、あはき法、療養費 | 広告できる事項が限定列挙、「〜が治る」「交通事故治療」「骨盤矯正」の可否、健保適用範囲の誤認NG、適応症の広告可否 |
| **C 施術系（無資格）** | 整体院／カイロプラクティック／リラクゼーション・もみほぐし | 法的資格なし→医業類似行為・景表法・あはき法の医業類似規制 | 「治療」「治す」「診断」「医学的」NG、医療機関と誤認させる表示NG、効果保証NG（← ウェルネ案件の勝ち筋と一致） |
| **D 美容・健康サービス** | エステサロン／脱毛サロン／痩身サロン／パーソナルジム・フィットネス／ヨガ・ピラティス | 特定商取引法（継続役務）、景表法、薬機法（美容機器） | 医療脱毛と誤認NG・「永久脱毛」は医療のみ、ビフォーアフター、痩身/減量効果の保証NG、特商法の役務・中途解約表示 |
| **E 物販・EC** | 健康食品・サプリ／化粧品・コスメ／医薬部外品／美容・健康機器／機能性表示・トクホ事業者 | 薬機法66/68条、健康増進法（誇大表示）、景表法、機能性表示制度、粧工連自主基準 | 身体変化・部位痩身・疾病予防治療の暗示NG、化粧品効能56項目・浸透は角質層まで、機能性表示の範囲逸脱（← 現行rulebookの中心） |
| **F 広告・支援業** | 広告代理店／Web制作・LP制作／アフィリエイター・ASP／インフルエンサー・SNS運用代行／PR会社 | 上記すべて（受託先業種に依存）＋景表法（表示主体責任）、ステマ告示（2023.10〜） | 制作物が受託先業種の規制を継承、ステマ（#PR明示・第三者装いNG）、薬機法66条は「何人も」＝個人でも適用、アフィリ広告の景表法運用基準 |

### 3.2 業種選択のUX
- 第1階層でカテゴリ（A〜F）、第2階層で具体業種を選ぶ2段選択。
- 「わからない／複数」を選べる。その場合は横断ルールのみ適用し、絞り込みを促す。
- 広告代理店（F）は「受託先の業種」を追加で選ばせる（規制の継承のため）。

## 4. 媒体（メディア）体系

媒体は「広告該当性」と要件を変えるため独立の軸として持つ。

| 媒体 | 規制上のポイント |
|---|---|
| LP（ランディングページ） | 典型的「広告」。医療は限定解除要件フル適用。誘引性MAX |
| HP・サービスサイト | 医療機関HPも2018から広告規制対象。限定解除でメニュー・料金・リスク明記 |
| バナー／リスティング広告 | 典型的広告。短文でも最大級・保証表現に注意 |
| SNS投稿（X/Instagram/TikTok） | ステマ規制が最重要。体験談・#PR・第三者装い |
| 記事・コラム（監修含む） | 記事広告／ネイティブアドは「広告」該当。監修者表示 |
| 動画（YouTube・広告動画） | 上記＋ビフォーアフターの動的表現 |
| チラシ・DM（紙） | 配布は誘引性あり＝広告 |
| 口コミ・体験談 | 医療は原則NG、物販はサクラ・ステマ（景表法） |
| 商品パッケージ・ラベル | 薬機法の法定表示＋景表法 |
| 院内掲示・待合ポスター | 医療広告の「広告」に当たらない場合がある（来院済み＝誘引性の議論）＝専門知の見せ所 |
| メルマガ・LINE配信 | 継続的勧誘、特商法・薬機法 |

### 4.1 業種×媒体マトリクスの扱い
- 業種と媒体の組み合わせで「適用する規制セット」「診断の重点観点」「限定解除チェックの要否」を切り替える。
- 実装は §7 の二層（一般マスター＋案件別）に加え、業種タグ・媒体タグでルールをフィルタしてからAIに渡す。

## 5. 機能要件

### 5.1 診断フロー（メイン動線）
1. 業種カテゴリ→業種を選択（§3）
2. 媒体を選択（§4）
3. 広告文／URL／画像（将来）を入力
4. エンジンが業種×媒体でルールをフィルタ→意味検索でヒット→AIが判定
5. 出力：総評／リスクスコア／該当表現・理由・条文・リスク区分（⛔⚠️🐧）・修正案／最終判定欄（`_META`準拠の現行フォーマットを踏襲）

### 5.2 診断エンジン（C1・C2の解決）
- **フィルタ層**：業種タグ・媒体タグで候補ルールを絞る（誤検知を構造的に減らす）
- **検索層**：単純一致に加え、意味検索（埋め込みベクトル）で言い換え・表記ゆれを拾う。上位10件足切りを廃し、スコア閾値＋動的件数に。
- **判定層**：Fable 5。フィルタ済みルール＋業種/媒体コンテキストを渡してJSON構造化出力（`output_config.format`）で受ける。
- 現行の堅牢JSONパーサは移行時に構造化出力へ置換（自前パースを減らす）。

### 5.3 リライト機能（既存メモ [[med-ad-diagnostic-rewrite-feature]] を正式取り込み）
- 投稿を貼ると、その業種×媒体で薬機法/景表法セーフな言い換えを返す。
- 将来のAPI卸しへの布石。Fable 5 の生成力が活きる中核機能。

### 5.4 課金・権限
- 現行Stripe（無料6回→個人¥500/法人¥5,000）を維持。
- リライト・業種横断・PDF出力などを有料機能として設計余地を残す。

### 5.5 出力・エクスポート（将来）
- 診断結果のPDF出力（まさの納品物・提案書に転用）。

## 6. データベース再設計（C5の解決）

### 6.0 法令マスター（法規データベース）― 今回の中核

> まさの指示：「関連法規を本気でデータベース化。私が把握しなくても正確なチェックができるツールを」。

現行の rulebook は「NG表現の事例集」。その**下に、法令・条文・ガイドライン・自主基準そのものを一次ソースで構造化した"法令マスター"を敷く**。各ルール（事例）は法令マスターのノードに `law_id` で紐づく。これにより：
- 「なぜNGか」を条文レベルの根拠つきで返せる＝正確なチェック
- まさが全法規を暗記していなくても、ツールが法令の構造を保持
- 法改正時は法令ノードを1箇所直せば、紐づく全ルールに波及

#### 法令マスターのスキーマ（案）
```
{
  law_id,                       // 例: L-VET-17
  category: "獣医療法",
  title: "獣医療広告の制限",
  article: "第17条 / 施行規則第24条",
  authority: "農林水産省",       // 所管
  summary,                       // 規制内容の要約
  applies_industries: ["G"],     // 適用業種
  applies_media: [...],          // 適用媒体（該当性に効く）
  key_points: [...],             // 判定に使う要点（限定列挙・限定解除要件 等）
  last_revised: "2024-04-01",    // 改正日
  source_url,                    // 一次ソース（省庁・e-Gov・協議会）
  source_type: "法律|政省令|GL|自主基準|運用基準"
}
```

#### 一次ソース主義
法令マスターの各ノードは、必ず一次ソース（e-Gov法令検索、所管省庁、公正取引協議会等）のURLを持つ。二次情報（弁護士解説等）は補助に留める。初版のソース索引は `docs/law_master.md` に構築（本ターンで着手）。

#### 対象法令（全業種・初版インデックス）
薬機法／景表法／健康増進法／医療法（医療広告GL）／柔道整復師法／あはき法／特定商取引法／機能性表示食品制度／粧工連自主基準／**獣医療法（獣医療広告制限）／ペットフード安全法／ペットフード表示公正競争規約**、ほか。詳細は `law_master.md`。

### 6.1 スキーマ刷新
タプル配列 → 意味のあるオブジェクトへ。案（正本 rulebook_master の列＋新規タグ）：

```
{
  id, ng, ok, comment,
  risk,                      // 0-100
  risk_band,                 // ⛔ / ⚠️ / 🐧
  law_ids: ["L-VET-17"],     // 法令マスター(§6.0)への紐づけ＝根拠の源泉
  law: [ {name, article} ],  // 表示用の条文（law_idsから展開）
  industries: ["A","C","E"], // 適用業種カテゴリ/業種（空=横断）
  media: ["LP","SNS",...],   // 適用媒体（空=横断）
  genre, jcia, source,       // 既存メタ
  embedding: [...]           // 意味検索用ベクトル（別テーブル/別ファイル可）
}
```

### 6.2 正本との整合（既存運用を壊さない）
- 正本は `00_System_管理/rulebook_master`（v15/610、id `1blakVB...`）。SOP（.xlsxコピー→openpyxl→拡張子なしへcp）は維持。
- v2用に **業種タグ・媒体タグの列を正本へ追加**し、`rulebook.json` 生成時にオブジェクト形式へ変換するビルドスクリプトを新設。
- 二層運用（[[legal-check-uses-rulebook]] / 案件別見解）はそのまま。判定優先順位＝【案件別見解 ＞ 一般マスター ＞ client_db】。

### 6.3 本物のDBへ（段階移行）
- 初期：`rulebook.json` を継続（デプロイ容易）。
- 拡張期：Supabase/Postgres＋pgvector へ。意味検索・更新・スケールの土台。移行は正本xlsx→DB同期ジョブを設計。
- タグ付けの初期投入は Fable 5 でバッチ自動分類→まさが検収、が現実的。

## 7. モデル戦略（Fable 5）

### 7.1 事実
- `claude-fable-5`：入力 $10 / 出力 $50（per 1M）、1Mコンテキスト、最大出力128K。
- 思考は常時オン（`thinking`は指定しない or `adaptive`。`disabled`は400）。深さは `output_config.effort`。
- 安全分類器で `stop_reason: "refusal"` が返り得る（法規・生物・サイバー隣接で誤検知あり）。→ **サーバー側 `fallbacks`（`claude-opus-4-8`）をデフォルトで入れる**。
- 30日データ保持が必須（ZDR不可）。プロンプト・アシスタントプリフィル不可、構造化出力は `output_config.format`。

### 7.2 コスト現実（正直に）
Fable 5 は Sonnet の約3.3倍・Opus 4.8の約2倍の単価。全診断を無条件にFableに載せると無料6回の原価が跳ねる。→ **段階採用を推奨**：
- リライト・難判定・業種横断など「生成力/難度が効く」処理を Fable 5。
- 定型のフィルタ済み一次判定は Opus 4.8 / Sonnet 5 も選べる二段構え（回帰テストで各モデルの品質を比較して決める）。
- 「最終的にFableで対応」の意図は満たしつつ、原価を制御する。

### 7.3 移行で必要な作業
- モデルID差し替え、`thinking`除去、構造化出力化、`fallbacks`＋beta header、回帰テスト整備。詳細は claude-api の移行ガイド準拠。

## 8. 非機能要件
- パフォーマンス：フィルタ＋意味検索で入力〜初回トークンを体感数秒。長文は逐次表示（ストリーミング）。
- 免責：「AIによる一次診断。最終可否はまさ（薬剤師）が確認」を明示（現行踏襲）。実名非表示ルール順守（署名は肩書名義）。
- セキュリティ：APIキーはサーバー側env、プレビュー安全ガード（実装済み）維持。
- 運用：ルール更新は候補インボックス→半自動反映フロー（RULEBOOK_RUNBOOK.md）を継続。

## 9. UI/UX要件（C6の解決・「プロ水準」の定義）

「素人でなくプロのアプリ制作者レベル」を受入基準として言語化する：
- 情報設計：業種選択→媒体選択→入力→結果の4ステップが迷わず進むステッパー/ウィザード。
- 視認性：リスク区分（⛔⚠️🐧）を色・アイコン・コントラストで即読。該当箇所は原文ハイライト。
- レイアウト：余白・タイポグラフィ・整列が一貫。モバイル最適（スマホで完結）。
- 状態設計：ローディング/空/エラー/上限到達（課金導線）を丁寧に。
- 一貫性：デザイントークン（色・間隔・角丸）を定義し使い回す。
- 「AIっぽい安っぽさ」を避ける：汎用フォント/紫グラデ/定型レイアウトを使わない。業種に合う落ち着いた配色。
- ブランド：Pharma-Ad Lab のトーン（信頼・専門・淡々）。

> 実装前に、この基準に沿った画面モックを1枚作って方向を合わせる（次アクション）。
