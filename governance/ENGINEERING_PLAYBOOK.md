# ENGINEERING_PLAYBOOK

このリポジトリは **public**。運用ルールをここに置く。非公開の情報は `.ai-private/` へ。

最終更新：2026-08-06

---

## 1. 権限

### 確認なしで実施してよい

リポジトリ・差分の解析、ローカルのコード変更、ローカルコミット、テスト、ビルド、静的解析、RFC・レビュー資料のローカル作成、改善提案。

### まさの明示承認が必要

GitHubへの push、PR の作成・更新・マージ、本番デプロイ、Vercel / Stripe / Anthropic / Upstash の設定変更、APIキー・秘密鍵の変更、課金が発生する処理、データ削除、公開ページの価格・プラン・法的表記の変更、既存仕様の大幅な変更。

「そのまま進めて」「完了まで進めて」等の一括承認があった範囲では、細かな確認を繰り返さない。

## 2. push 前チェック（毎回）

1. `git status` と `git diff main...HEAD` を全件確認
2. 追跡対象に `.env` 系が入っていないか（`.env.local.example` のみ可）
3. `.vercel/` `.ai-private/` が追跡されていないか
4. シークレットスキャン：`sk-ant-` / `sk_live` / `sk_test` / `pk_` / `whsec_` / `AKIA` / `-----BEGIN` / 長い16進・base64
5. 内部文書（RFC、レビュー資料、脆弱性の再現手順）の混入
6. 本番 Deployment と HEAD SHA の一致

**publicリポジトリに絶対に入れないもの**：APIキー、Stripe秘密鍵、Upstashトークン、`APP_TOKEN_SECRET`、`.env`、Vercelの内部設定、個人情報、脆弱性の悪用コマンド、未修正脆弱性の再現手順、内部RFC、非公開ルールブック、個人的な文脈。

## 3. セキュリティ修正の公開手順

publicリポジトリのため、**修正が本番に届く前に差分を公開しない**。

1. ローカルで修正・テスト
2. Vercel CLI でプレビューへ反映し確認
3. 本番へ反映し確認
4. **その後に** push・PR作成
5. PR本文には、影響の概要／修正内容／テスト結果／本番反映済みである旨／ロールバック方法／未確認事項のみを書く。攻撃手順・再現コマンド・悪用方法は書かない

## 4. テスト

```bash
npm run test:security   # 利用枠・レート制限・請求ポータル。外部通信なし＝無料
```

- AI も Stripe も実際には呼ばない。Stripe はモックに差し替える
- 本番コードは ESM だが package.json は CJS 扱いのため、テストはソースを一時ディレクトリへ `.mjs` として展開して読み込む。**production 側のコードにテスト用の細工を入れない**

## 5. 設計上の決めごと

### 利用枠

- 回数の正本はサーバー側。クライアントからの申告値は一切使わない
- **AI を呼ぶ前に枠を予約し、失敗したら戻す。** 確認してから加算する方式は、同時リクエストで上限を超える
- 加算・上限判定・巻き戻しは Lua スクリプト1本で不可分に実行する
- メモリフォールバック側も、加算と判定の間に `await` を挟まない

### 秘密鍵

`APP_TOKEN_SECRET` が無い場合、既定値へフォールバックして動作を継続しない。**fail closed** を基本とし、診断APIは 503 で停止する。

### 個人情報

IPアドレスは復元できない形（`APP_TOKEN_SECRET` を鍵とした HMAC）に変換してから保存する。保持期間は用途ごとに最短にし、**プライバシーポリシーの記載と実装を必ず一致させる**。

### モデル

- `DIAGNOSE_MODEL` で切り替えられる状態を保つ
- モデル固有のパラメータ（`fallbacks` 等）は、対象モデルのときだけ送る
- 価格・仕様は記憶で断定せず、公式の一次情報を確認し確認日を添える

## 6. 数字の扱い

対外に出す件数・比率・価格は、出典と定義を確認してから使う。定義が複数並存している間は訴求に使わない。

## 7. 既知の環境上の制約

- 開発ディレクトリが iCloud 上にあるため、`next build` が webpack のキャッシュ書き込みに失敗して完走しない。ビルドの成否は Vercel 側（プレビューデプロイ）で確認する
- Vercel Hobby プランは Function Region が1つのみ

## 8. 作業の締め

各作業の終了時に `.ai-private/HANDOFF.md` を更新する。ブランチ、HEAD SHA、本番 Deployment ID、本番にだけ存在する設定、open PR、完了・未完了、次の作業、判断待ち、最新のテスト結果を残す。
