## D-008　動画広告を受託領域に加える。売るのは映像制作ではなく工程管理

- 日付：2026-09-10
- 状態：**検討中**（領域を加えることはまさの決定。売り方の設計は提案であり、まさの確認待ち）
- 関連：D-007

### 決まっていること（まさ）
動画広告を受託領域へ加える。`pages/consult.js` に商品として掲載した。

### 提案（要確認）
提供するのは映像制作能力ではなく、**動画にしかない法務論点を工程で潰す体制**とする。根拠は3つ。

1. 編集作業は市場単価3,000〜8,000円／本の労働集約で、1人会社の時間単価と釣り合わない。自分で編集すると1本4〜6時間かかり、原価が2万円を超えて価格が崩れる
2. 生成AI動画は実在の店舗・スタッフ・患者を作れない。イメージ映像には使えるが、実在の医療機関の紹介には構造的に向かない。医療の文脈で実在しない人物を医療従事者や患者らしく見せること自体にも誤認のリスクがある
3. 一方で動画には**表示秒数・音声・編集演出**という、文字広告のチェックでは検出できない論点がある。ここは薬剤師×薬機法の知見が直接効き、かつ秒数は機械で測れるため1人会社でもスケールする

### この決定に基づいて実装したもの
- 法令マスターに動画ノード `L-VIDEO-DISCLAIM` / `L-VIDEO-AUDIO` / `L-VIDEO-BA`。`media=video` のときだけ適用され、他媒体の診断結果は変わらない
- 検収の機械判定：`npm run audit:video`（`lib/videoAudit.js`）。読了速度・最低表示秒数・打消し表示と強調表示の同時性・PR表記の位置・必須項目・禁止語を判定し、NGがあれば終了コード1
- 運用設計 `docs/video_ops.md`、事例1号 `docs/case_hashizume_recruit.md`

### 未確定
- 単価。原価から逆算した下限は1本40,000円（外注編集5,000円＋まさ2.5時間×4,500円、粗利6割）。掲載は「内容に応じてお見積もり」のままにしてある
- `lib/videoAudit.js` の閾値は実務上の設計値であって、行政が定めた基準値ではない
- 動画ノード3件は `verified: false`。開発環境から caa.go.jp / mhlw.go.jp へ到達できず一次ソースPDFを読めていない

## D-007　対外に出すルール件数を「773件」の1つに絞る

- 日付：2026-08-07
- 状態：**採用**
- 決定者：まさ
- 関連：D-005（本決定により撤回）

対外的に用いる件数は **773件＝広告表現チェックに使える現場ルールの件数** の1つとする。他の数字は対外訴求に使わない。

| 数字 | 中身 | 扱い |
|---|---|---|
| **773** | 広告表現チェックに使える現場ルール（重複除去後、容器包装表示専用を除く） | **これだけを使う** |
| 650 | 正本 rulebook_master の総ルール数（容器包装表示専用10件を含む） | 使わない（用途が違う） |
| 831 | 重複を含む展開前の件数 | 使わない |
| 827 / 640 / 636 | 過去の表記 | 使わない |

定義が割れていた原因は2つあり、いずれも解消した。

1. 正本には**容器包装（パッケージ）表示専用のルール**が含まれる。これは消費者庁の食品添加物の不使用表示ガイドライン由来で、広告を規制しない。広告診断へ機械適用すると構造的な誤検知になるため、`scripts/build-rulebook-v2.mjs` で `^食品表示_` を除外している
2. ルールデータの一部に**完全重複**が含まれていた（内容までバイト単位で同一）。同じビルド処理で除去し、除去件数を標準出力と `meta.deduped` に必ず出す

件数の算出はビルドが行い、`data/stats.json` の `rule_count` が唯一の出所になる。**数字を手で書かない。**

## D-005　ルール件数を対外訴求に使わない（定義が確定するまで）

- 日付：2026-08-06

## D-004　診断モデルを環境変数で切り替え可能に保ち、当面は Sonnet 5 を使う

- 日付：2026-08-05
- 状態：**採用（暫定）**

既定モデルでは応答が実行時間の上限に達し、診断が成立しない状態だった。`DIAGNOSE_MODEL` で切り替え、当面は応答時間と原価の両面から Sonnet 5 を用いる。

モデル固有のパラメータは対象モデルのときだけ送る（無条件に送ると切り替え時に400になる）。

恒久対応（実行時間上限の見直し、ストリーミング、難判定のルーティング）は後続で扱う。価格・仕様は記憶で断定せず、公式の一次情報を確認して確認日を添える。

## D-002　利用枠は「予約してから使い、失敗したら戻す」

- 日付：2026-08-05
- 状態：**採用**

上限を確認してから成功後に加算する方式は、同時に到着したリクエストが全て上限未満と判定されて通り抜ける。AI呼び出し前に枠を予約し、加算・上限判定・超過時の巻き戻しを Lua スクリプト1本で不可分に実行する。

AI失敗・タイムアウト・応答解析失敗時は予約を戻す。利用者が結果を受け取れなかった回数を失わないため。

## D-001　publicリポジトリでは、修正が本番に届く前に差分を公開しない

- 日付：2026-08-05
- 状態：**採用**

セキュリティ修正をGitHubへ先に出すと、修正が利用者に届く前に弱点の所在が公開される。ローカル → プレビュー → 本番の順で反映し、**その後に** push・PR を行う。

PR本文には影響の概要・修正内容・テスト結果・本番反映済みである旨・ロールバック方法・未確認事項のみを書き、攻撃手順や再現コマンドは書かない。
